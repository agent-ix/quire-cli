## Summary

Ticket: PLAT-1606. This is a code review with the rust-review lane folded in (rust-style loaded). It is scoped to `git diff origin/main...HEAD` (three commits, c1b1429, bd3ae61 and 045c2f8). It was checked against FR-034, FR-035, FR-032, FR-031, FR-040, NFR-004, NFR-010 and StR-004.

The PR reads the committed blob, the commit, the tag and the `.gitattributes` of the input in process with gitoxide component crates. It refuses uncommitted, untracked, outside and filtered input, and builds the six-field identity. It then writes `in/metadata.yaml` (Markdown-escaped JSON strings under `quire-export`), `in/front.md` (title page, raw page breaks and contents), a Typst template and a hand-written stored-ZIP DOCX reference document into the capability root. It sets `SOURCE_DATE_EPOCH` to the committer time.

Measured on this host:
- `cargo test --test cli_export` gives 39 passed and 5 ignored. The `export` unit tests give 10 passed.
- `cargo fmt --check` and `cargo clippy --all-targets --all-features -D warnings` are clean.
- `cargo deny check bans licenses sources` passes, and `deny.toml` is unchanged by the PR.
- Manual repros were run in a scratch rig with the real `engineering-assurance` 0.8.1 and stand-in converters: strace execve; a linked worktree; packed refs and packed objects after `git gc` with an annotated tag; a malformed committer time; `.git/info/attributes`; attribute macros; integer `version`; a non-repository `--source-repo`; an abbreviated rev; a leading-space title.

Dependency claim, verified:
- `gix` 0.90.0 depends non-optionally on `gix-protocol` 0.68.0, which depends non-optionally on `gix-transport` 0.62.0. With `gix-transport` banned in `deny.toml`, the `gix` facade cannot be used.
- `cargo tree -i gix-transport` and `cargo tree -i gix-protocol` match no package. `gix-command` is absent too, so the `gix-object` signing code that launches gpg/ssh is not compiled.

## Verdict

CHANGES REQUIRED. FND-001 is a spec violation that FR-034-AC-6 exists to catch: the export launches `git`. The rest of the identity path is sound, verified by hand:
- The committed blob is read from the object store, and the CRLF-normalised comparison is applied.
- The committer (not author) time comes from `CommitRef::time`, and the UTC civil date is correct for the AC-3 instant.
- A malformed committer time is refused, not defaulted.
- `--release` is peeled through annotated tags and compared with the source commit.
- Linked worktrees resolve through `commondir` and `Store::for_linked_worktree`.
- Packed refs and packed objects work.

The generated inputs are sound:
- Identity values reach the converter only through `in/metadata.yaml` and `in/front.md`. They are Markdown-escaped, and the metadata is serialised as JSON strings.
- The raw blocks in `front.md` are constants of the output format.
- The pandoc argument order equals the FR-032 table.
- `SOURCE_DATE_EPOCH` is the committer time.
- The JSON path is unchanged: no template, no front matter, no epoch, metadata `{}`.

There is no `unsafe`, no committed binary or template fixture, and no pin, SHA or digest ceremony. The tests build their git repositories at test time with the `git` binary in the harness only.
