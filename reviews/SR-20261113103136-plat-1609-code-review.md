## Summary

Ticket: PLAT-1609. Code review with the rust-review lane folded in (rust-style loaded), scoped to `git diff origin/main...HEAD`. The production change replaces `epoch: Option<i64>` with a plain `i64` and gives a JSON report `SOURCE_DATE_EPOCH=0`. Before it, a JSON report request had no `SOURCE_DATE_EPOCH`, so pandoc (`getTimestamp`, which reads that variable in the unsandboxed DOCX writer) and typst stamped the export time into `docProps/core.xml` and the PDF info. The leak was real, and the fix closes it.

Independent leak audit of the export path (not taking the coder's word): no `SystemTime`, `Instant`, `chrono`, `time::`, `modified()`, hostname, user or `env::var` read on the path from input to request. The only `env::var_os` is `PATH` for tool resolution, and the only `metadata()` is an `is_file()` check in custom.rs. Identity dates come from the git commit (gix, `utc_date`). The DOCX reference zip has fixed DOS time 0 and date 1980-01-01. The Typst template has no `datetime.today()` and no `set document(date:)`, so typst uses `SOURCE_DATE_EPOCH`. Converter arguments are all relative literals (`in/…`, `typ/…`, `out/…`). The environment holds exactly HOME, TMPDIR (both inside the capability root) and SOURCE_DATE_EPOCH, so TZ, LANG and USER never reach a converter. Host paths in the request (`executable`, `capabilityRoot`) and in error text never reach converter input or the output.

The three stand-in tests pass locally (3 passed, 1.95s). They really do vary cwd, output directory, TMPDIR (and with it the capability root), HOME and TZ. The `<ROOT>` normalisation replaces only the capability root, which occurs only in `capabilityRoot`, `HOME` and `TMPDIR`. The generated inputs and the output are compared raw and searched for the rig root and `quire-export-`, so the normalisation hides no leak. The `Rig::requests` numeric sort is correct: the old lexical sort put `10.json` before `2.json`, which broke `split_off(before)` once a rig made 10 or more requests.

## Verdict

Changes requested on the tests only. The production change is correct and minimal, with no Option-to-i64 regressions, and an independent audit found no other wall-clock, random-id, temp-name, host-path, user, locale or TZ leak into converter input, arguments, environment or generated parts. Nothing is vendored, and the diff adds no pins, SHAs or digests. FND-001 and FND-002 are medium because the real tests can pass while a leak exists. FND-003 to FND-005 are low. Rebase risk only: PLAT-1610 edits the same `epoch:` lines in export.rs, bundle.rs and producer.rs, so expect trivial textual conflicts.
