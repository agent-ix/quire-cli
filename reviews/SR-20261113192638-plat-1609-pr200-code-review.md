## Summary

Ticket: PLAT-1609. Code review with the rust-review lane folded in (rust-style loaded), scoped to `git diff origin/main...HEAD` of PR #200. The PR makes the 22 real-converter export tests pass with pandoc 3.14, typst 0.15.1, poppler 22.02 and mmdr 0.3.1. It changes test oracles and fixes two engine defects: approval-table column widths (`column_widths`) and a double page break after a bundle's front matter. `make test-export-real` was re-run on this head: 22 passed, 0 failed.

## Verdict

**CONDITIONAL**: there are no high findings. The bundle page-break fix is correct. The single-document front matter still ends with a page break (`list.is_none()`), and the stand-in tests still assert three raw blocks there (tests/cli_export.rs:970, template.rs:562). A bundle front now holds 2 `#pagebreak()`. The real DOCX bundle test now asserts exactly one page break before each separator, so it would catch the old double break. The PDF footer test computes `M` from the real page count, so page numbers stay checked.

The weaker date oracle does not let a wall-clock leak through. A DOCX date passes only if it starts with the commit time or with `1970-01-01T00:00:00`, and an export-time 2026 date matches neither. PDF dates must still equal the commit time. I reproduced the pandoc behaviour: under `--sandbox`, pandoc 3.14 writes 1970-01-01T00:00:00Z with `SOURCE_DATE_EPOCH=981261000`, and without `--sandbox` it writes 2001-02-04T04:30:00Z. The other oracle changes keep their tests able to fail:

- `pdfimages` counts `image` rows.
- `EMU_PER_METRE` is 36,000,000, so a pHYs density in pixels per metre now converts correctly. The old 914,400 was EMU per inch.
- The headerless mmdr fixture is now prose, so mmdr really rejects it.
- The approval and row-id checks compare with whitespace removed (and hyphens removed in PDF), and they still need every value present.

No tool-version pins, digests or other ceremony were added; the Makefile only names the tools. The two medium findings below are open: the column-width fix does not hold for a real-length record digest, and a new unit test is tagged to an unrelated criterion. Gates on this head:

- `cargo fmt --check`: clean.
- `cargo clippy --workspace --all-targets --all-features -D warnings`: clean.
- `--bin quire export::` unit tests: 21 passed.
- `--test cli_export`: 91 passed and 1 failed in each of three runs. A different test failed each time, with `containment_failure: producer-execute could not contain the converter`. That is the known EA-115 flake, not a PR defect.
