## Summary

Ticket: PLAT-1603. This is a code review with the rust-review lane folded in (rust-style loaded). It is scoped to `git diff origin/main...HEAD` (one commit, 5c7a2e2). It was checked against the PLAT-1603 acceptance criteria and against FR-031 section B, FR-033, StR-004 (the bounded exception) and NFR-010. Report shapes were checked against the real producers: `quire matrix --format json` run on this repository, and quoin `origin/main` (91619f67), specifically `soup/report/render.rs`, `discharge/rmm.rs`, `discharge/pack_rmm.rs`, `discharge/report.rs` and `quoin-cli/src/discharge.rs`.

The PR adds `src/commands/export/json.rs`. It parses the report as a `serde_json::Value` and builds a Markdown pipe-table text for each `--kind`, escaping every ASCII punctuation character and turning control characters into spaces. It hands that text to the existing `producer::convert` path, and only after shape checking. It also turns on `serde_json/preserve_order` crate-wide.

Measured on this host:
- `cargo test --test cli_export` gives 28 passed and 2 ignored. The ignored ones are the real-converter tests; pandoc, typst and pdftotext are not installed here.
- The PR binary's `quire parse spec/functional/FR-031-export-subcommand.md` emits frontmatter keys as `id, title, type, relationships`. The main-equivalent installed `quire` 0.44.0 emits `id, relationships, title, type`. The data is equal and only the bytes differ.
- `quire export mixed.json --kind table`, with `{"items":[{"id":"A"},5],"others":[{"id":"B"}]}`, passes the shape check and goes on to converter resolution. All of `items` is dropped.
- `cargo tree -e features -i serde_json` shows that quire-cli is the only normal-dependency enabler of `preserve_order`. tree-sitter enables it only as a build dependency.

## Verdict

Changes requested. FND-001 and FND-002 are code fixes for this PR. FND-003 and FND-004 need a short FR-031 amendment in the same PR, because the code follows the current FR-031 text. FND-005 to FND-008 are low.

These parts were checked and are correct:
- **Escaping is injection-safe at the Markdown layer.** Pandoc `markdown` (`all_symbols_escapable`) treats a backslash before any ASCII punctuation as a literal. That covers `\|` inside a pipe table, raw HTML or OpenXML `<`, raw TeX `\`, `$` math, backtick raw-attribute spans, `@` citations, `:::` divs and `|` line blocks. Every C0/C1 control character, plus U+2028 and U+2029, becomes a space, so no cell can split a row. The heading, `As of:`, bullet and header texts are all escaped. Typst and OpenXML escaping is then the pandoc writers' job, and no raw block can reach them.
- **Errors come before any converter.** `to_markdown` runs, including the pack pre-check of every matrix, before `Converters::resolve`, so a shape error never resolves or starts a tool (FR-033-AC-6, FR-031-AC-10).
- **No new execution path.** The JSON route reuses `producer::convert` and `write_output`, so `engineering-assurance producer-execute` stays the only launch site (NFR-010-AC-1), and no network crate was added.
- **No other rows are dropped** in `matrix`, `rmm` or `soup`. Every element of `rows`, `criteria`, `index`, `matrices`, a non-empty `unusedFacts`, `unmatched` and `scans` is rendered, and an empty member still gets its heading. Gap rows (`untagged`, `undischarged`, `undetermined`) render like any other row.
- **The accepted shapes match the real producers** at the top level. `quire matrix --format json` emits `{coverage_matrix:[{document, criteria:[{id,statement,method,binders,status}]}], engine}`. The rmm forms have `schemaVersion`, `clauseSet{authority,id,version}`, `asOf`, `rows` and `unusedFacts`. The pack form has `schemaVersion`, `pack`, `asOf`, `context`, `index[{clauseSet,rowCount}]` and `matrices`. The soup report has `as_of`, `rows` with the 14 FR-031 members, `unmatched`, `scans` and `unreadable_scans` (a string array).
- **The `table` kind skipping scalar members** matches FR-031 ("one table per such member"), so it is not a defect. Only the mixed-array case in FND-002 is.
- **No panics.** `row[index]` is in bounds because every cell row is built over the same `columns`, and the width arithmetic (`chars().count()`, `clamp`) cannot overflow.
- **Nothing is vendored, and there are no pins or SHA ceremony.** The fixtures are fictional.
