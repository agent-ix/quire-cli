## Summary

Ticket: PLAT-1611. This is a code review with the rust-review lane folded in (rust-style loaded). It is scoped to `git diff origin/main...HEAD` (two commits, de2fdf0 and 6ab27fe; origin/main has not moved past the merge base aa3bcf0). It was checked against FR-039, FR-031, FR-032, FR-034, FR-035 and FR-040. The `--approval` block of FR-039 (FR-038, PLAT-1610) is out of scope.

The PR turns `<INPUT>` into `Vec<PathBuf>` and routes more than one input, or one Markdown input with a bundle option, to the new `bundle` module. `check_request` refuses, in order: fewer than two inputs, more than 256 inputs, a missing `--bundle-title` and/or `--bundle-id`, a non-Markdown input, an input equal to `--output`, then the shared flag checks. `resolve_sources` then reads and identifies every input in order, applies the single-repository rule (the shared git dir), and validates every committed blob. Only after that are the converters resolved. The producer writes `in/separator-<n>.md` and `in/document-<n>.md` and passes them after `in/front.md`.

Measured on this host at 6ab27fe (CARGO_PROFILE_DEV_DEBUG=0, locked-build lane):
- `cargo fmt --check` is clean.
- `cargo clippy --all-targets --all-features -- -D warnings` is clean.
- `cargo test --test cli_export` gives 55 passed, 0 failed, 8 ignored.
- `cargo test --bins export` (the export unit tests) gives 12 passed.
- Manual repro: two linked worktrees of one repository, HEADs dfc7b45 and 148482e, one committed FR in each. `quire export main/a.md wt/b.md --bundle-title T --bundle-id B-1 --pandoc /nonexistent/pandoc` passes identity, the repository rule and validation, and stops only at converter resolution ("missing converter"). With a real converter it would export (FND-001).

## Verdict

CHANGES REQUIRED, for FND-001 and FND-002. The rest of the change is sound, checked by hand:
- Input order is kept, and so is a repeated input: the sources are a `Vec` in argument order, with no dedup.
- Every input is read, identified, checked against the repository rule and validated before `Converters::resolve`, so no converter starts on a bad input. The first failure names its file.
- The request-level refusals (fewer than 2 inputs, more than 256, missing options, a non-Markdown input) come before any file is read.
- The bundle title, bundle id, document ids, titles and versions all pass through `escape_markdown` before they reach `front.md`, the document-list pipe table or a separator. A pipe becomes `\|`. The raw blocks are constants of the output format.
- The pandoc argument order equals the FR-032 table: front.md, then separator-n and document-n. There is no `--shift-heading-level-by` and no `--table-of-contents`.
- The single-input path still writes and passes `in/document.md`.
- A JSON input with a bundle option is refused naming the flag.
- The capability root and its cleanup are unchanged.
- 256 inputs give 2n+3 files and 525 arguments, well under the executor's `MAX_ARGUMENTS` of 4096.
- The `Vec<PathBuf>` change touches only `export.rs` and `json.rs`, and nothing else builds `export::Args`.
- Nothing is vendored, and there is no pin, SHA or digest ceremony.

Observations for the owner (not defects of this PR):
- The ticket's AC asks for "three DOCX files plus an index". The merged FR-039 asks for one output file, and it is consistent with itself (Description, Behavior B and AC-1 all describe one DOCX). The coder followed the spec, which is correct. The ticket text should be brought in line with FR-039.
- PR #190 (PLAT-1607, `--template`) will conflict textually in `src/commands/export.rs` (the `Args` struct, the `check_flags` arms, and `&args.input` against `&args.input[0]` in `export_markdown`) and at the end of `tests/cli_export.rs`. It also conflicts in meaning: `bundle::run` always uses the default template, so whichever PR lands second must pass `--template` into the bundle path.

## Verdict addendum (disposition pass 1)

Template wiring, new in 92d769a:
- `bundle::run` loads `--template` through PR #190's `custom::load`, after the request checks and `check_output_target`, and before any source is read. Repro: an invalid template with an uncommitted input reports the template error first ("--template 'nope.docx': the extension must be .typ", exit 3).
- The error kinds and exit codes are the same as on the single path: exit 3 for a wrong extension, a missing path, a directory or a file above 16 MiB; exit 2 for a permission refusal.
- The loaded bytes replace the default template for PDF and DOCX, and the producer writes them unchanged to `in/template.typ` or `in/template.docx`.
- The FR-032 argument list is unchanged: the template flag and `in/` path, then front.md, then separator-n and document-n. `a_bundle_applies_the_organisation_template_unchanged` asserts the whole argument vector and the copied bytes for both formats.
- No user path reaches an argument.
- `a_bundle_with_an_invalid_template_exits_3_before_any_converter` asserts exit 3 naming the path, no request, and an unchanged pre-existing output.
- This is consistent with FR-036 (bytes copied unchanged, no fallback to the default template), FR-039 and FR-040.

The real-converter tests stay ignored, because pandoc, typst and pdftotext are not installed here. They are accepted as deferred and non-blocking.
