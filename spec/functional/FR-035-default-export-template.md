# FR-035: Default export template: title page, contents, headers, footers, page numbers

## Description

When `quire export` of a Markdown input gets no `--template`, it SHALL apply a
default template that gives the document the standard parts of a controlled
copy. The default template is generated by the export code at export time into
the capability root; no template file is stored in this repository or package
([NFR-010](../non-functional/NFR-010-export-single-converter-single-path.md)).

## Behavior

### A. Parts

The default template SHALL produce, in this order:

1. **Title page**: the title, then the identity fields of
   [FR-034](./FR-034-document-identity.md) as labelled lines (Document id,
   Version, Release when present, Source commit, Date), and nothing from the
   body. When approvals are supplied ([FR-038](./FR-038-approval-block.md)), the
   approval block follows the body, not the title page.
2. **Table of contents**: headings of level 1 to 3 of the body, with page
   numbers in PDF, and a table-of-contents field in DOCX.
3. **Body**: the artifact as [FR-031](./FR-031-export-subcommand.md) section A
   specifies.

### B. Headers, footers and page numbers

- Every page after the title page SHALL carry a header holding the document id and
  the Version (or Release when no Version) and a footer holding the first 12
  characters of the source commit hash and the page number in the form
  `Page N of M`.
- The title page carries no page number.
- In DOCX the page number and page count are the word-processor fields `PAGE`
  and `NUMPAGES`, so they stay correct when the document is edited.

### C. Layout

The default template fixes the page size (A4), margins, fonts and heading styles
inside the generated template, so they do not depend on the host. It uses only
fonts that the converter bundles or declares as generic families, and it adds no
image.

## Acceptance Criteria

| ID | Criteria | Verification |
| --- | --- | --- |
| FR-035-AC-1 | A PDF export of a committed fixture with no `--template` yields page 1 text with the title and the five identity fields and no body text, and the text of page 2 onward holds the body. Extracted with `pdftotext` per page. | Test |
| FR-035-AC-2 | The PDF holds a table of contents whose entries equal the fixture's level 1 to 3 headings in order, and the DOCX holds a TOC field. | Test |
| FR-035-AC-3 | PDF pages after the first hold a header with the document id and version, and a footer with the 12-character commit prefix and `Page N of M` for the page's own N and the total M; page 1 holds no `Page 1 of`. | Test |
| FR-035-AC-4 | The DOCX footer part holds the `PAGE` and `NUMPAGES` fields and the 12-character commit prefix. | Test |
| FR-035-AC-5 | The repository tree and the package file list hold no `.typ`, `.docx` or `.dotx` file for the default template, and the default template reaches the converter only through the capability root. | Inspection |
| FR-035-AC-6 | A fixture with no headings still exports, with an empty table of contents, and the title page is unchanged. | Test |
